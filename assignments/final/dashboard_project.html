Final Project - Building Interactive Dashboards with Quarto

Submission Guideline: Create a separate Quarto dashboard (.qmd file) for each question. Put the links to all your dashboards on your GitHub page and submit the link of that page to Canvas.

  • Questions 1 and 2 are static dashboards. Render them and publish the .html file on your GitHub page like your other assignments.
  • Questions 3 to 10 are interactive dashboards (they use Shiny). Publish them on Posit Connect Cloud and submit the app links.

Before you start:

  • Update RStudio to version 2026.04 or later (Help -> Check for Updates).
  • Install the packages shiny, rsconnect, tidyverse, plotly, DT, and lubridate.
  • Read the Quarto dashboard guide and the Shiny and Quarto Dashboards slides.

Templates: every question below links to a template. Download the .qmd file, put it in its own folder, and change it. All templates read the Titanic data from the course website, so they run without any extra files.

Question 1.

Create an empty Quarto dashboard and render it.

Dashboard and Template

  1. In RStudio, create a new Quarto Document (File -> New File -> Quarto Document) and delete everything in it.

  2. Copy the code of the empty template into the file and save it in a new folder.

  3. Click Render. The result should look like the Dashboard above: two pages, a sidebar, and four empty cards.

  4. Change the title, the page names, and the card titles. Render it again.

How the layout works:

  • format: dashboard in the YAML header makes the document a dashboard.
  • # Page name (one #) creates a page. The page names appear as tabs in the top navigation bar.
  • ## {.sidebar} inside a page creates a sidebar on that page.
  • ## Row and ## Column arrange cards. Use {height=30%} or {width=50%} to size them.
  • Each code chunk becomes a card. ### Card title or #| title: Card title gives the card a title.

Question 2.

Create a static dashboard with:

  • a sidebar
  • at least three pages
  • at least four plots
  • at least one value box
  • a searchable data table

Use the Titanic data or your own data.

Dashboard and Template

Notice:

  • On a page with a sidebar, the sections after the sidebar are laid out as columns. To put a row of value boxes above a row of plots, put both rows inside one column (## Column, then ### Row and ### Row), as in the template’s Overview page.
  • #| content: valuebox turns a chunk into a value box. The chunk returns list(icon = ..., color = ..., value = ...). Icon names come from Bootstrap Icons.
  • DT::datatable() gives a table with a search box.
  • ggplotly() from the plotly package makes a ggplot interactive (hover, zoom).
  • ## Column {.tabset} shows the cards in that column as tabs.

Question 3.

Publish your first interactive dashboard on Posit Connect Cloud.

  1. Look at the selectInput dashboard, then download its template and save it as a .qmd file in a new folder. Put logo.png in the same folder.

  2. Click Run Document (the button that replaces Render when the YAML has server: shiny) to run the dashboard on your computer.

  3. Go to https://connect.posit.cloud and create a free account. Signing up with your GitHub account is the easiest choice.

  4. In RStudio, click the blue Publish icon at the top right of the editor, choose Posit Connect Cloud, sign in, and follow the instructions. In the Publish dialog, tick only the .qmd file and logo.png.

  5. When publishing finishes, the dashboard opens in your browser. Copy its link; this is the link you submit.

Alternative: publish from GitHub. If the Publish button does not work for you:

  • Put the .qmd file and logo.png in a folder of a public GitHub repository.
  • In R, set that folder as the working directory and run rsconnect::writeManifest(). This creates a manifest.json file that lists the R version and packages your dashboard needs.
  • Commit and push all files, including manifest.json.
  • On https://connect.posit.cloud click Publish, pick your repository, branch, and the .qmd file.
  • If you add packages later, run rsconnect::writeManifest() again and push the new manifest.json.

How an interactive dashboard works:

  • server: shiny in the YAML header runs the dashboard with Shiny.
  • The #| context: setup chunk loads packages and data. It runs once.
  • Inputs (selectInput(), sliderInput(), …) go in the sidebar.
  • Output chunks hold plotlyOutput("p1"), DTOutput("tbl"), and so on.
  • The #| context: server chunk is the server: it fills the outputs with renderPlotly(), renderDT(), … and uses input$... to read the inputs.

Recommended: create two Posit Connect Cloud accounts. A free account can hold only a few dashboards, and Questions 3 to 10 ask for eight. Create a second free account with a different email address, then connect both accounts to RStudio:

  1. In RStudio, go to Tools -> Global Options -> Publishing, click Connect…, choose Posit Connect Cloud, and sign in with your second account.

  2. Both accounts are now listed under Publish from account in the Publish dialog. Pick the account you want each time you publish a dashboard.

  3. Split your dashboards between the two accounts, for example Questions 3 to 6 on the first account and Questions 7 to 10 on the second.

If an account is full, publishing fails with the message “Your account has reached its maximum applications limit”. Publishing to a full account can also stop dashboards already on that account from working. Before publishing, delete dashboards you no longer need on https://connect.posit.cloud, or publish to your other account.
